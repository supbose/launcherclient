- 目标：在 `src-egui` 用 egui/eframe 复现 src-tauri + Vue 前端的更新程序界面（默认模板 C），
  复用现有业务逻辑避免重复实现。
- 共享化改造（**本次最重要的架构变动**）：把原本散落在 src-tauri/src-zsui `updater.rs` 与
  Vue `usePhase.js` 的内容抽到 `src-core`：
  - `src-core/src/phase.rs`（459 行）：`Stage`/`PhasePayload`（与 Tauri emit 载荷字段一致）/
    `PhaseHandle`(Arc<Mutex<Option<..>>>)/`PhaseView`（percent/size_text/speed_text/eta_text/
    show_progress/step 全部派生，step==-2 表示 error 阶段沿用上一步）/`format_bytes`/
    `resolve_template_key`/`STEP_LABELS`。
  - `src-core/src/flow.rs`（1027 行）：`ResolvedConfig`/`StartupDecision::Show(Box<..>)`/
    `run_startup`/`spawn_flow`/`spawn_flow_with`/`run_update_flow`/`run_download_parts`/
    `SpeedTracker`/`resolve_launch_exe`/`launch_target`/`finish_and_launch`/`retry` 等完整编排。
  - `src-core/src/lib.rs` 追加 `pub mod flow; pub mod phase;`。
  - src-tauri / src-zsui 均通过 cargo check 验证未破坏。
- src-egui 结构：`main.rs`(CLI 预处理+--preview/--stage) / `theme.rs`(CSS 色值常量+字体注入) /
  `widgets.rs`(自绘 标题栏/进度条/环形/spinner/日志卡/按钮) / `templates.rs`(A~E 五套布局) /
  `app.rs`(eframe App 的 logic+ui) / `preview.rs`(照搬 Preview.vue 的 8 个阶段预设)。
- **eframe 0.35 API 与旧版本差异大**（踩坑记录，复用时注意）：App trait 拆成 `logic()`+`ui(&mut Ui)`；
  没有 `clear_color`；没有 `ctx.screen_rect()` → `ui.max_rect()`；没有 `Ui::allocate_new_ui` →
  `ui.new_child(UiBuilder)`；`painter_at()` 返回值而非引用；`Mesh::add_triangle(u32,u32,u32)`；
  `Shape::mesh()` 包 Arc；`Color32::from_rgba_unmultiplied_const` 才能用于 const；
  `all_styles_mut(|s| ..)` 需闭包；`ViewportBuilder::default()`；creator 返回 `Result<Box<dyn App>, Box<dyn Error>>`。
- **必须手动注入中文字体**（egui 自带字体无 CJK → 豆腐块）：装 `C:/Windows/Fonts/msyh.ttc`，
  并 insert 到 Proportional/Monospace 首位。
- 编译 egui-winit 在高并行下触发 rustc ICE(ACCESS_VIOLATION)，改用 `cargo build -j 2` 通过。
- 验证：`src-core` 单测 134 passed；src-tauri/src-zsui cargo check 通过；src-egui debug+release build 通过；
  用本地 mock 更新服务器（8MB zip + 限速 + sha256）跑通真实更新全流程；`--stage N` 预览模式
  用 GDI 截图脚本抓取 13 张模板/阶段组合 → `docs/egui-preview-shots/`。
