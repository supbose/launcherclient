## 实测反馈修复：更新完成自动关窗 + 窗口居中（src-egui）

- 用户实测反馈：① 安装完成、目标程序已启动，但更新器窗口停在「更新完成」不关闭；
  ② 启动器窗口未水平垂直居中。
- 根因：Tauri 版在自家 updater.rs 里拉起成功后 `app.exit(0)`，而共享 `flow.rs` 只返回
  `Ok(())` 没有退出信号；tauri.conf.json 有 `"center": true`，egui 无 `with_center`。
- 修复：
  - `phase.rs`：`PhaseHandle` 新增 `exit: Arc<AtomicBool>` + `request_exit()` / `exit_requested()`。
  - `flow.rs`：三处启动成功后 `handle.request_exit()`（run_update_flow 完成分支、
    run_check_flow 无更新分支、finish_and_launch）。
  - `app.rs`：帧循环轮询 exit 信号发 `ViewportCommand::Close`（删除 EXIT_AFTER_FINISH 静态标志）；
    首帧读 `ViewportInfo.monitor_size + outer_rect` 发 `ViewportCommand::OuterPosition` 居中，
    窗口 `with_visible(false)` 隐藏启动、居中后 `Visible(true)`，30 帧兜底。
- 验证：居中偏差 (0,0)；真实端点全流程（0.4.27，28 分卷）后更新器 51.1s 自动退出码 0；
  134 单测 + 兄弟 crate check + clippy + release 全绿。
- 踩坑记录：
  - **cargo check 不产出 exe**，验证运行时行为前必须 cargo build（曾用旧 exe 测出假 FAIL）。
  - manifest 覆盖参数是 `--manifest` 不是 `--manifest-url`（cli.rs），传错会被静默忽略。
  - `target/release/.cargo-build-lock` 可能残留且 rm 报拒绝访问 → 沙箱放行后删除即可。
  - 伪目标程序验证法：rustc 单文件编译 `#![windows_subsystem="windows"] fn main(){}` 为 qsm.exe，
    放进 mock zip 根部，`find_main_executable` 会命中且启动即退、不闪控制台。

## Tauri vs egui 性能对比实测（2026-10-26）

- 天然对照组：本仓库 `src-tauri` 与 `src-egui` 是同一个更新程序的两套 UI 实现
  （同 440×420 窗口、同后端 `src-core`、同 mock manifest），差异只剩 UI 框架。
- 实测结论（Win11 x64 / release / 本地 mock 限速 200KB/s，3 轮取中位）：
  - 体积：Tauri 11.1MB（+dist 116KB 外置）/ egui-wgpu 15.4MB / egui-glow **9.7MB**
    → 「Tauri 体积最小」不成立，glow 后端比 Tauri 还小。
  - 首窗可见：Tauri 主窗口 835ms（splash 757ms 串行等待）/ egui-wgpu 776ms / egui-glow 558ms。
  - **进程树**峰值内存：Tauri 353.6~361.9MB（WebView2 子进程占 316.9MB，主进程仅 32.9MB）
    / egui-wgpu 177MB / egui-glow 161.6MB → **Tauri 是 egui 的 2~4 倍**。
  - 下载渲染活跃期 CPU（进程树）：Tauri 43.3% / egui 10.6% → **Tauri 约 4 倍**。
  - GPU 引擎利用率：Tauri 0~0.7% / egui 0~1.7% → 两者都极低，小界面瓶颈不在 GPU。
  - 进程数：Tauri 3~7 个（browser/GPU/renderer/utility）/ egui 恒 1 个。
- **测量陷阱（关键）**：只测主进程会把 Tauri 内存低估 10 倍（WebView2 在独立子进程）。
  必须按进程树求和（CreateToolhelp32Snapshot 找父子关系 + GetProcessMemoryInfo）。
  GPU 用 `Get-Counter '\GPU Engine(*)\Utilization Percentage'` 并按 PID 归属过滤。
- eframe 0.35 的 default feature 实际是 **wgpu**（不是 glow）。`src-egui/Cargo.toml` 注释
  写的「glow 渲染后端，默认 feature 即可」与实现不符，建议修正注释或切 glow。
- 报告产出：`docs/Tauri-vs-egui性能对比.md`（含测量方法与复现命令）。
- 测量脚本（D:/tmp/）：measure_perf.py / measure_windows.py（按标题区分 splash 与主窗口）/
  measure_tree.py / measure_repeat.py / measure_active.py / measure_gpu.py。
