## splash loading 页对齐 qsm 方案（commit 5c6139c）

背景：用户反馈「没有更新时没有 loading 页面」「双击白屏」。经 0.5s 粒度窗口
时间线探针（D:\tmp\probe_v4.py，PrintWindow 截图不可用改纯枚举）实测定位。

### 改动
- `src-tauri/tauri.conf.json`：声明 splash 窗口（qsm 同款配置项：
  280×160、decorations:false、alwaysOnTop、skipTaskbar、visible:true），
  直接运行模式「声明即创建」，首帧早于 setup 动态创建
- `src-tauri/src/lib.rs` setup：交接模式（--launch）立即 close splash
  保持静默；直接运行模式 mark_splash_shown()
- `src-tauri/src/updater.rs`：MIN_SPLASH_DISPLAY_MS=1000 +
  SPLASH_SHOWN_AT OnceLock + ensure_min_splash_display()，无更新退出前
  补足最短展示（先补足再 close_splash，等待期间保持界面）
- 关闭方式与 qsm main.rs show_main_and_close_splash 同构：
  show main → 150ms → close splash

### 关键实测发现
- **WebView2 窗口销毁耗时 ~1s**：close() 调用后窗口约 1s 才消失。
  交接模式 splash 闪现 1s 即此耗时（qsm 无交接模式故无此问题）。
  备选方案已验证可编译：splash 配置 create:false + setup 里
  WebviewWindowBuilder::from_config 构建（交接模式零窗口零闪现）
- 无更新快路径：manifest 秒回时原实现 splash 只闪 0.5s 即退出，
  用户看不到 loading（本次修复点）
- update.json 的 launch 配置（无更新拉起目标）与命令行 --launch
  （交接静默）是两个语义：前者 setup 保留 splash，后者 setup 关闭
- Tauri 2.12.4 时序（src/app.rs:2691-2699）：setup() 先建配置窗口、
  再执行 setup hook —— 静态声明窗口在 hook 里操作必然已存在

### 验收矩阵（release 实测）
| 场景 | 结果 |
|---|---|
| 直接运行+慢检测 | splash 0.6s 出现 → 失败 main 出现 → splash 按序关闭 |
| 交接模式+慢检测 | splash 闪现 ~1s 后关闭（已知代价），失败显示 main |
| 无更新 | splash 展示 ~2s 后关闭、拉起 qsm、退出 |
