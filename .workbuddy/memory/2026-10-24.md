# 2026-10-24

## 修复：launch 留空时首次安装/无更新不拉起应用程序

- 现象：update.json `launch: ""` 时，启动器检测完更新直接消失，应用不启动；安装完成后也不自动拉起（原设计停在「完成」按钮）。
- 根因：tauri 版 [src-tauri/src/updater.rs](../../src-tauri/src/updater.rs) 两处「手动模式」分支不拉起应用：
  1. 无更新分支 `None => app.exit(0)` 静默退出；
  2. 安装完成分支只打印日志等待用户点「完成」。
  启动器（launcherclient）语义下用户双击就是要启动应用，留空只应表示「目标程序自动定位」。
- 修复：两分支均改为 `find_main_executable(安装目录, app_name)` 自动定位 + `spawn_detached` 拉起，
  失败显示错误窗口（与 launch 配置分支对称）；「完成」按钮 finish_and_launch 保留为兜底。
- 语义文案同步：config.rs generate_default_template 模板说明、cli.rs `--launch` 注释、
  finish_and_launch 注释——「留空 = 自动定位安装目录主程序（文件名与应用名匹配者优先）」。
- zsui 版（src-zsui）为**冻结版**（2026-10-20 起不同步修，见其 updater.rs 内注释），本次未动。
- 验证：src-core 113 tests + src-tauri 7 tests 通过；真实冒烟 `--current-version 0.4.23`
  强制无更新分支，qsm.exe 被成功拉起（托盘/后端/主窗口日志齐全）。
- 现场：本机 %APPDATA%\qsm 已装 0.4.22（10-24 5:28 经 debug 配置 launch="qsm.exe" 更新），
  服务器已有 0.4.23；src-tauri/target/debug/update.json 是独立部署配置（测试后已恢复 launch="qsm.exe"）。
- 环境噪声：Windows 链接器「正在创建库 *.lib」输出被 cargo 当 warning，非代码问题。
