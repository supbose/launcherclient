## launcherclient：构建脚本统一为 pybuild.py（egui / pkgtool 双目标）

需求：pkgtool 的 release 构建改成与 `egui:build` 一样的 pybuild 程序（版本号同步 + cargo release + 产物校验）。

改动：
- `scripts/build_egui.py` 泛化为 `scripts/pybuild.py`（旧脚本删除，零兼容）：`TARGETS = { egui: src-egui/version.rc→launcherclient, pkgtool: src-pkgtool/icon.rc→pkgtool }`，四步流程不变（读 package.json 版本 → 写目标 rc 四处版本字段并回读校验 → cargo build --release → powershell 核对 exe 内嵌版本号）。
- `package.json`：`egui:build` → `python scripts/pybuild.py egui`；`pkgtool` → `python scripts/pybuild.py pkgtool`（原先只是裸 cargo build，不同步 icon.rc 版本）。
- README 同步更新：目录树、第 3 节构建命令与版本号同步说明（现在两个 pybuild 目标都会同步各自 rc）。

验证：`python scripts/pybuild.py`（无参报用法退出 2）、`pybuild.py pkgtool` 与 `pybuild.py egui` 全量跑通，两个 exe 内嵌版本号均为 0.1.32.0；icon.rc / version.rc 已同步为 0,1,32,0。

## launcherclient：build.py 全量打包 → dist/<版本号>/

需求：一个脚本依次跑两个打包，产物按版本号归档。

改动：
- `pybuild.py` 抽出 `build_target(target, csv, dotted) -> exe 路径`（同步 rc → cargo release → 校验产物），`main()` 改为调用它，单目标行为不变。
- 新增 `scripts/build.py`：读 package.json 版本 → 依次 `build_target(egui)`、`build_target(pkgtool)` → `shutil.copy2` 产物到 `dist/<版本号>/`（launcherclient.exe + pkgtool.exe）。dist 已在 .gitignore。
- `package.json` 新增 `"dist": "python scripts/build.py"`；README 第 3 节补充说明。

验证：`pnpm dist` 全链路跑通，`dist/0.1.32/` 下两个 exe 内嵌版本号均核对为 0.1.32.0。
