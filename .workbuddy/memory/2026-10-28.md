# 2026-10-28

## launcherclient：更新前管理员权限检查 + runas 提权

背景：截图报错「服务 QsmServer 卸载失败：权限不足（退出码 5）」。原 `services.rs` 仅在 `sc delete` 失败后才把退出码 5 翻译成「权限不足」提示（被动）。本次把检查前移为主动提权。

改动（src-core）：
- 新增 `src-core/src/elevation.rs`：Windows 令牌提权检测 `is_elevated()`（OpenProcessToken + GetTokenInformation(TokenElevation)，raw extern 链接 kernel32/advapi32/shell32，**无额外 crate 依赖**）；`relaunch_self_elevated()` 用 ShellExecuteW("runas") 重新拉起自身（携带相同参数 + 内部标记 `--__elevated-retry` 防死循环）。非 Windows 提供恒真/恒 ok 桩。
- `flow.rs::run_update_flow` 开头接入 `elevation::ensure_admin_for_update(cfg)`：仅当「配置了 `cfg.services` 且当前未提权」才触发（安装落 LocalAppData 不需管理员）。拉起成功 → 退出当前进程由提权副本接管；拉起失败（用户取消 UAC）→ 置错误态「需要管理员权限」并 return Err。`services.rs` 的退出码 5 文案保留为防御兜底。
- `cli.rs` 静默忽略内部标记 `--__elevated-retry`。
- 新增 8 个单测（needs_elevation_for / ensure_admin_for_update_with 各分支），全部通过；src-core 全量 153 测试通过；src-egui 编译通过。

验证：`cargo check`（src-core、src-egui）、`cargo test`（src-core 153 passed）。
注意：本机沙箱对 target 增量锁文件报「拒绝访问」(os error 5) 属环境噪声，与改动无关。

## launcherclient：版本检查「强制更新」开关（force_update）全链路落地

需求：update.json 新增 `force_update` 开关 + `store_url`；manifest 新增 `min_version`/`force_update`；开关启用且当前版本 < 最低版本（或被标记强制更新）时阻断启动并提示必须升级（清晰展示当前/要求版本号）；关闭时仅非阻断提示可稍后升级；界面提供「前往应用商店 / 下载升级包」入口。

改动：
- src-core/src/manifest.rs：`FlatManifest` 增 `min_version`/`force_update`；新增 `is_below_min_version`/`is_forced_update`/`requires_force_update`/`required_version`。
- src-core/src/config.rs：`UpdateSettings` 增 `force_update`/`store_url`；`resolve_force_update`/`resolve_store_url`；模板说明与默认值。
- src-core/src/phase.rs：`Stage::ForceUpdate`；`PhasePayload::force_update(...)`；`PhaseView` 增 `is_force_update`/`is_blocking`/`has_store`/`force_current`/`force_required`。
- src-core/src/flow.rs：`ResolvedConfig` 增 `force_update`/`store_url`；`run_startup` 强制更新前置判定（Save 分支，manifest 回传供 UI 拉起）；`check_only_exit` 退出码 3=触发强制更新；新增 `open_store_url()`。
- src-egui/src/widgets.rs：`Action` 增 `Store`/`ForceDownload`/`ForceLater`；`force_update_actions_row()`。
- src-egui/src/templates.rs：新增共享 `draw_force_update()`（警示图标+标题+当前/要求版本对比卡+动作行），接入 A~H 八套模板（`match` 内 `return` 提前退出，避免误渲染日志卡片）；`draw()` 透传 `store_error`。
- src-egui/src/app.rs：`force_manifest`/`store_error` 字段；Show 分支对强制更新**不自动 spawn**，仅存 `force_manifest`，由按钮驱动（阻断无「稍后升级」）；`match action` 消费三新动作（Store→open_store_url、ForceDownload→spawn_flow_with、ForceLater→finish_and_launch）。
- src-egui/src/preview.rs：STAGES 增「强制更新（阻断）」/「强制更新（可稍后升级）」预览阶段。
- update.json：增 `force_update`/`store_url` 字段+说明；version.json.example：增 `min_version`/`force_update` 说明与示例。
- 顺手修两处既有 clippy：`flow.rs` 的 `map_or→is_some_and`；app.rs/main.rs 的 `Mutex::lock().unwrap()→unwrap_or_else(|e| e.into_inner())`（项目 `unwrap_used=deny`，属改动前既有，已一并消除）。

验证：`cargo check`（src-core、src-egui）通过；`cargo test --lib`（src-core）**162 passed**；`cargo clippy`（src-core --lib、src-egui，含 bin）无 deny 级告警（仅 build.rs 的 `expect_used` 为 -W 级既有告警）。
注意：本机沙箱对 target 增量锁文件报「拒绝访问」(os error 5) 属环境噪声。
