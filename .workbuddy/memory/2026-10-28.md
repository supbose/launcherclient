## launcherclient：force_update 语义调整（按用户澄清）

用户澄清：现状「有更新就必须更新」= 普通更新（need_update）走 Available 自动下载、无跳过出口。此前实现把 `force_update` 开关绑在「服务端门槛（min_version / 服务端 force_update 标记）」上，导致普通更新仍是强制——与用户「有更新可不更新、进应用」的诉求不符。

新模型（用户确认：默认 false=可跳过；本地开关 + 服务端门槛两套并存）：
- 服务端硬性门槛（requires_force_update：当前版本 < min_version 或服务端标记 force_update）→ 始终**阻断**强制更新（无「稍后升级」）。
- 本地 `force_update=true` → 普通更新也强制，走 Available 自动下载（=改动前「有更新必须更新」）。
- 本地 `force_update=false`（默认）→ 普通更新可跳过，进入非阻断 ForceUpdate 界面（「发现新版本，可稍后升级」），展示 当前→最新版本，「稍后升级」→finish_and_launch 进应用。

改动（仅 src-core/src/flow.rs + update.json 说明）：
- `ResolvedConfig.force_update` 注释改为「本地开关控制普通更新可跳过性，默认 false」。
- `run_startup`：原「前置判定 + need_update/else」两段重写为 `if !need_update / else if server_forces(阻断) / else if cfg.force_update(自动) / else(可跳过)` 四路；可跳过分支 `let latest = m.version.clone()` 后 `manifest: Some(m)` 移动（修掉借用错误）。
- `check_only_exit` 文档与 `run_check_only`：有更新且 `cfg.force_update` 时也返回退出码 3（必须更新）；否则 2（可跳过）。
- update.json `_说明` 的 force_update/store_url 文案更新为「本地开关 / 默认 false=可跳过 / 服务端门槛始终阻断」语义。
- app.rs/widgets.rs/templates.rs/phase.rs/manifest.rs/config.rs 无需改动（已支持）；`force_update` 默认 false 已符合新默认。

验证：`cargo check`（src-core、src-egui）通过；`cargo test --lib`（src-core）**162 passed**；`cargo clippy`（src-core --lib、src-egui）无 deny 级告警。

## launcherclient：force_update 最终决策（更正，2026-10-28）

用户最终澄清：`force_update` **不应在本地 update.json，应是服务端 version.json（manifest_url 下载的 manifest）里的参数**。强制更新是服务端下发策略，客户端不能本地关闭强制，否则强制无意义。已移除本地开关：config.rs（`UpdateSettings.force_update`/`resolve_force_update` 删除）、flow.rs（`ResolvedConfig.force_update` 删除 + 两处 `cfg.force_update` 分支删除）、elevation.rs（测试字面量删除）、update.json（字段与说明删除）。`force_update` 仅作为服务端 `FlatManifest` 字段保留（manifest.rs），由服务端下发。

最终模型：
- 服务端 manifest 的 `force_update`（版本级强制标记）**或** `min_version`（最低允许版本）任一成立 → `requires_force_update` → **阻断**启动，无「稍后升级」出口。
- 否则有更新但服务端未强制 → 非阻断 ForceUpdate 界面（「发现新版本，可稍后升级」），「稍后升级」→ `finish_and_launch` 进应用。
- 本地 update.json 仅保留 `store_url`（应用商店入口，缺省回落 homepage）。
