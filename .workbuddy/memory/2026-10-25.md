# 2026-10-25

## 更新程序服务卸载报错修复（src-core/src/services.rs）

- 现象：更新时报「服务 QsmServer 卸载失败（sc delete 退出码非零: false）」，更新终止。
- 根因诊断：① 旧错误信息本身有 bug，打印的是 `o.success`（恒为 false）而非退出码，现场无法定位；
  ② 最可能诱因：更新程序未以管理员身份运行（sc delete 需提权，非提权返回 5 拒绝访问；
  或上一轮失败残留「标记删除」状态 1072）。安装目录走 %APPDATA% 不需要管理员，因此程序常在非提权态运行。
- 改动：
  - `ScOutput` 新增 `code` / `stderr` 字段，`SystemScRunner` 改用 `sc.exe` 绝对路径并保留退出码与原始输出。
  - 新增 `failure_code` + `delete_with_retry`：按退出码分流（1060=视为已卸载；1072=短重试，仍失败提示重启；
    5=提示需管理员；其余带 sc 原始输出）。错误信息不再只显示「false」。
  - 同步重写单元 mock（query/stop/delete 各自队列）并新增 6 条覆盖退码分流的测试。
- 验证：`cargo test -p qsltd-updater-core` 全绿（119 passed）。公开 API 未变，src-tauri/src-zsui 调用点不变。
- 后续建议（未做）：在最终打包 exe 嵌入 requireAdministrator 清单，使更新程序默认提权；或启动前检测 IsUserAnAdmin 并提示。
